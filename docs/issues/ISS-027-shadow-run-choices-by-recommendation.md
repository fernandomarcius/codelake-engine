# ISS-027 — Shadow-run harness: choices applied by recommendation

- Kind: behavior · Applied: 2026-09-25 · Status: awaiting-confirmation
1. `codelake config import` never guesses a hive catalog's `INT96` time zone: `hive.parquet.time-zone` becomes `parquet_time_zone`; without it, the zone comes from `--reference-time-zone` (the reference engine's JVM zone), or the catalog is skipped. The alternative, CodeLake's default (`America/Sao_Paulo`) or the stock image's (UTC), shifts every `INT96` timestamp silently when it is the wrong one.
2. The harness ships an expected-differences file with ISS-018 (name case) only, applied only when a run names it (`SHADOW_EXPECTED_DIFFERENCES=default` or a path). Revised after the audit: a `declared_type` rule must name one exact table and column, so ISS-019 (`varchar(n)` → unbounded) is declared per column of the project. The alternative, one project-wide ISS-019 rule, cannot tell a literal from a source column and classified finding F8-2 (a SQL Server `varchar(n)` length lost) as expected in the self-test. No rule covers values.
7. The self-test fixture works around findings F8-1..F8-3 (candidate defects on the acceptance pipelines' patterns) behind the dbt variable `shadow_workarounds`, so the harness is proven while they are open; `SHADOW_SELFTEST_STRICT=1` runs without them and fails. The alternative, a self-test that cannot pass until the connector and planner are fixed, proves nothing about the harness.
3. Declared columns (names, order, types) come from each table's metastore file, also for tables without data files; a metastore file on one side only is a divergence; without one on both sides, the Parquet schema stands for them. Revised after the audit: Parquet storage that differs under equal declared types (INT96 vs INT64 timestamps, decimal widths, timestamp units) is a divergence, and `INT96` values are compared as the wall-clock time of `SHADOW_PARQUET_TIME_ZONE` (not compared without it). The alternative, storage as a warning with `INT96` read as stored, reported a table rewritten with every timestamp 3 hours off as equal.
8. A configured RSS gate (`SHADOW_RSS_MAX_RATIO`) needs a meter on both sides, and a cycle where a side was not measured fails; `SHADOW_TABLES` entries that are not `schema.table` are refused. The alternative, skipping the gate or the entry silently, let a cycle pass without the check it was configured for.
4. Partitioned tables are refused (reported as an error, which fails the cycle) rather than compared; neither acceptance pipeline partitions.
5. Views are listed as not compared (no data files); the tables built from them are compared.
6. A SQL Server catalog with `encrypt=false` imports as `encrypt = "off"` with `trust_server_certificate = true`: the JDBC driver encrypts the login without validating the certificate, and the source does the same only with both. The alternative, validating the certificate, fails to connect wherever the reference engine connects today with a self-signed certificate.
- Revisit when: confirmed or overturned by a human; item 2 when ISS-018/ISS-019 are implemented; item 4 if a pipeline partitions; item 7 now that F8-1 is known to hide a wrong value (the workaround rounds like the reference).
- References: ADR 0015, docs/shadow-run.md, ADR 0007 (`parquet_time_zone`).
